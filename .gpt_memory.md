# Project Memory

- Project: `affiliate` at `/Users/letrongthien/Downloads/projects/affiliate`.
- Purpose: local AI affiliate-video studio / MCP server. Backend manages generated videos, S3 metadata/publishing, FFmpeg processing, Gemini/Veo pipeline; React client manages videos/products and generation workflow.
- Stack:
  - Backend: Node.js + TypeScript + Express 5, MCP SDK, AWS S3/Bedrock, OpenAI, FFmpeg (`ffmpeg-static` + local fallback), Sharp.
  - Frontend: React 19 + TypeScript + Vite 8, lucide-react.
- Main entry points:
  - `src/bootstrap.ts`: backend bootstrap; loads runtime guards before dynamically importing `server.ts`.
  - `src/server.ts`: Express API, video CRUD/pipeline/FFmpeg endpoints. Large file; use `searchCode` for targeted inspection rather than reading whole file.
  - `client/src/App.tsx`: client shell/dashboard and modal wiring.
  - `client/src/components/video/VideoPlayerModal.tsx`: main video review/edit modal.
  - `client/src/components/dashboard/VideoCard.tsx`: video gallery card/actions.
  - `client/src/components/storyboard/PartEditorModal.tsx`: per-storyboard-part image/video editor.
  - `client/src/components/modals/GenerateVideoModal.tsx`: full 6-part generation orchestration and per-part render calls.
- Video trimming architecture / decisions:
  - Generic POST `/api/videos/trim-start` in `src/server.ts` removes N seconds from the beginning, rewrites the video, and may re-upload to S3. Backend clamps `trim_seconds` to 0.1..30.
  - Storyboard parts have a richer existing API: POST `/api/pipeline/trim-part-video` accepts `product_name`, `scene_index`, `start_sec`, `end_sec`, `from_original`; it creates a one-time `.orig.bak` backup before trimming. POST `/api/pipeline/restore-part-video` restores that backup.

- Veo generation/download reliability discovery (2026-09-16):
  - `GenerateVideoModal.tsx:L770-L797` calls `/api/pipeline/generate-single-scene-video`; any HTTP/API/download failure makes `handleRenderSingleVideo()` return `false`.
  - `GenerateVideoModal.tsx:L1037-L1043` stops Run All immediately on the first false and replaces the useful backend reason with the generic `Part N chưa tạo xong video hoặc tải về thất bại...`, so the persistent status hides the real error.
  - There was no retry loop for per-part Veo generation in the React full-flow/batch path.
  - `src/veoAutomation.ts:L2039-L2040` falls back from CDP/browser download to plain HTTP `downloadFile(capturedVideoUrl, targetPath)`; `downloadFile` is at `src/veoAutomation.ts:L971+` and uses an HTTP stream without the authenticated Chrome session cookies.
  - Concrete repo evidence of the auth-download bug: `data/downloads/gau-dudu-va-bubu-i-an-mi-ramen/gau-dudu-va-bubu-i-an-mi-ramen_part2_k4yl45x7.mp4` is actually Google Accounts sign-in HTML (`<!doctype html>...accounts.google.com...`) rather than MP4. Google `contribution.usercontent.google.com/download` redirects unauthenticated HTTP fallback to login.
  - Current validation at `src/veoAutomation.ts:L2059-L2060` mainly checks existence/size (`>=300KB`), which can allow a large HTML login page to masquerade as `.mp4`.
  - Server single-scene endpoint accepts both `image_url` and optional `scene_image_path` (`src/server.ts:L3590-L3591`) and passes them to `generateSingleVeoSegment` (`L3618-L3621`), so the React `image_url` field alone is not the primary cause of this recurring download failure.
- Veo reliability fix applied 2026-09-16:
  - Added `src/googleDownloadAuthPatch.ts`. It patches only axios GETs targeting Google user-content video download URLs. The fallback now reads the logged-in Google cookies from the existing Chrome CDP session (`CHROME_DEBUG_PORT`, default 9222), adds those cookies plus Gemini referer/Accept headers, retries the authenticated download once, and rejects Google Accounts/sign-in or HTML responses before they can be written as fake `.mp4` files.
  - Added `src/bootstrap.ts` so the axios guard is installed before `server.ts` / `veoAutomation.ts` are evaluated.
  - Updated root `package.json`: `dev:server` now runs `src/bootstrap.ts`, production `start` runs `build/bootstrap.js`, and `main` points to `build/bootstrap.js`.
  - Added `client/src/runtime/videoGenerationRetry.ts`, imported by `client/src/main.tsx`. Only POST `/api/pipeline/generate-single-scene-video` gets one transparent retry for transient 502/503/504 or download/auth/local/video-file style failures. This is intentionally capped at 2 total attempts to avoid excessive duplicate Veo generations/credits.
  - The backend authenticated download retry is the primary fix; the client whole-generation retry is a safety net for transient failures.
- Original trim UX problems that motivated the fix: no preview, no duration validation, only destructive start trimming in React, a quick-card action that immediately modified the file, and an overly dense/imbalanced trim panel layout.
